# طرح UI موبایل «انی‌تیل» (Anitale): سند پیاده‌سازی برای OpenCode

> این سند طراحی کامل نسخه‌ی موبایل است. تصویر `anitale-mobile-preview.png` مرجع بصری چهار صفحه‌ی اصلی است. اگر بین متن و تصویر تفاوتی دیدی، متن ملاک است.

## ۰. قواعد کلی (اول این‌ها را بخوان)

1. **نسخه‌ی دسکتاپ نباید تغییر کند.** همه‌ی تغییرات فقط زیر breakpoint موبایل اعمال می‌شود. کاربر از دسکتاپ راضی است.
2. **breakpoint موبایل: `max-width: 820px`.** این همان نقطه‌ای است که در CSS فعلی چیدمان سه‌ستونه تک‌ستونه می‌شود. طرح قبلی موبایل (topbar چندردیفه با `flex-wrap`، `sidebar` و `right-column` زیر محتوا) کاملاً کنار گذاشته می‌شود و از صفر ساخته می‌شود.
3. **کامپوننت‌های جداگانه‌ی موبایل بساز** (مثلاً `components/mobile/*`) و با یک hook مثل `useIsMobile()` (matchMedia روی `(max-width: 820px)`) یا با کلاس‌های `md:hidden` / `hidden md:block` بین دو نسخه جابجا شو. روی CSS قبلی موبایل patch نزن.
4. **تم همان تم فعلی است.** از توکن‌های موجود (`--background`, `--primary`, `--card`, `--border`, `--secondary`, `--accent`, `--muted-foreground`, `--radius`) استفاده کن. رنگ جدید اختراع نکن. تم تاریک (`.dark`) هم باید با همین توکن‌ها خودکار کار کند، پس مقدار hex ثابت ننویس.
5. **RTL اول.** سایت `dir="rtl"` است. فقط از logical properties استفاده کن (`margin-inline-start`, `inset-inline-end`, `padding-inline`, `text-align: start`). هرجا `left/right` لازم شد، دوباره فکر کن.
6. فونت همان **Vazirmatn Variable** فعلی است. چیزی اضافه نکن.
7. محتوای متنی، نام صفحه‌ها و روت‌ها همان‌هایی است که هست. فقط ظاهر و ساختار عوض می‌شود.

## ۱. ایده‌ی طراحی

**«پوستر اول، ابزار در دسترس شست.»** در موبایل، کاور انیمه مهم‌ترین عنصر است و ناوبری باید با یک شست قابل دسترس باشد. پس:

- ناوبری اصلی از بالا به **tab bar شناور پایین** می‌آید.
- صفحه‌ی خانه با یک **hero تمام‌عرض و پوستری** شروع می‌شود (همان گرادیان آلوییِ تیره‌ی دسکتاپ روی پوستر).
- بقیه‌ی محتوا **ریل‌های افقی** و **لیست رتبه‌بندی** است، نه گرید چندستونه.
- فیلترها در **bottom sheet** هستند، نه نوار کنترل چندردیفه.
- در صفحه‌ی جزئیات، دکمه‌ی اصلی («افزودن به فهرست») همیشه پایین صفحه چسبیده است.

عنصر ماندگار طرح: hero پوستری + tab bar شیشه‌ای. بقیه‌ی عناصر عمداً ساکت و منظم‌اند. روی هیچ چیز دیگری انیمیشن تزئینی نگذار.

### ۲.۳ فضا، شعاع، سایه

- **فاصله‌ی افقی صفحه: 16px.** بین سکشن‌ها 22px. بین عنوان سکشن و محتوا 12px.
- شعاع‌ها: کاور 14px، کارت/ردیف 18px، hero 30px، sheet بالای 30px، دکمه 15–17px، pill (چیپ، سرچ) 999px، tab bar 26px.
- سایه‌ها همان لحن آلویی سایت: `0 1px 2px #2f1d2b0d` برای کارت‌ها، `0 10px 22px -14px #6732578c` برای کاور، `0 18px 36px -14px #4f2e4466` برای tab bar. خاکستری خنثی نگذار.
- حداقل ناحیه‌ی لمس همه‌ی عناصر قابل کلیک: **44×44px** (دکمه‌ی آیکونی 40px هم با padding نامرئی به 44 برسد).
- پایین هر صفحه‌ی دارای tab bar: `padding-bottom: calc(66px + 12px + env(safe-area-inset-bottom) + 16px)`.

## ۳. ساختار کلی (App shell)

```
┌──────────────────────┐
│ TopBar (52px, sticky)│  لوگو+نام · جستجو · آواتار
├──────────────────────┤
│                      │
│  محتوای صفحه          │
│  (اسکرول عمودی)       │
│                      │
├──────────────────────┤
│ BottomTabBar (شناور)  │  خانه · انیمه · مانگا · فهرست من · بیشتر
└──────────────────────┘
```

- صفحه‌های سطح‌اول (خانه، انیمه، مانگا، فهرست من) هم TopBar دارند هم TabBar.
- صفحه‌های داخلی (جزئیات انیمه/مانگا، پروفایل کاربر، مقاله، ...) **TabBar را مخفی می‌کنند** و به‌جایش ActionBar یا هیچ. TopBar آن‌ها فقط دکمه‌ی بازگشت و اکشن‌ها را دارد.
- سایدبار، `right-column` و `section-rail` دسکتاپ در موبایل **رندر نمی‌شوند**. محتوای آن‌ها در «بیشتر» یا ریل‌های خانه می‌رود (بخش ۵).

## ۴. کامپوننت‌ها

### ۴.۱ `TopBar`
- ارتفاع 52px، `position: sticky; top: 0; z-index: 40`.
- پس‌زمینه: `color-mix(in oklch, var(--card) 72%, transparent)` + `backdrop-filter: blur(18px) saturate(1.5)` + خط پایین `inset 0 -1px` از `--border`. (همان استایل شیشه‌ایِ topbar دسکتاپ)
- از راست به چپ (RTL): لوگوی ۳۰px گرد (گرادیان `--primary`) + «انی‌تیل» 18px/800 ← فضای خالی ← دکمه‌ی جستجو (40px، سفید، شعاع 14px، حاشیه‌ی `--border`) ← آواتار 36px.
- اگر کاربر وارد نشده: به‌جای آواتار دکمه‌ی کوچک «ورود» (pill با `--secondary`).
- **لینک‌های ناوبری دسکتاپ (`nav-links`) و `search-box` در موبایل نیستند.** جستجو با ضربه روی آیکون، یک overlay تمام‌صفحه باز می‌کند (بخش ۵.۵).
- در صفحه‌ی داخلی: دکمه‌ی بازگشت (آیکون `chevron` به سمت راست در RTL) سمت شروع، اکشن‌ها (اشتراک‌گذاری و غیره) سمت پایان. روی پس‌زمینه‌ی بلور جزئیات، دکمه‌ها شفاف‌شیشه‌ای‌اند.

### ۴.۲ `BottomTabBar`
- `position: fixed; inset-inline: 12px; bottom: calc(12px + env(safe-area-inset-bottom)); height: 66px; border-radius: 26px; padding: 7px; z-index: 20`.
- پس‌زمینه: `color-mix(in oklch, var(--card) 80%, transparent)` + `backdrop-filter: blur(20px) saturate(1.6)` + `box-shadow: inset 0 0 0 1px color-mix(in oklch, var(--border) 70%, transparent), 0 18px 36px -14px #4f2e4466`.
- ۵ آیتم برابر (`flex: 1`)، هرکدام آیکون 22px + برچسب 10.5px/700 زیر آن:

| ترتیب (راست به چپ) | برچسب | مسیر |
|---|---|---|
| ۱ | خانه | `/` |
| ۲ | انیمه | `/anime` |
| ۳ | مانگا | `/manga` |
| ۴ | فهرست من | `/dashboard` (اگر وارد نشده: `/login`) |
| ۵ | بیشتر | باز کردن sheet «بیشتر» |

- **حالت فعال:** پس‌زمینه‌ی `--accent`، رنگ `--accent-foreground`، شعاع 20px. حالت عادی: `--muted-foreground`.
- آیکون‌ها: خطی (stroke 1.8، گوشه‌ی گرد)؛ از همان کتابخانه‌ی آیکون پروژه استفاده کن اگر دارد، وگرنه `lucide-react` (`Home`, `Tv`, `BookOpen`, `ListChecks`, `LayoutGrid`).
- هنگام اسکرول رو به پایین نیازی به مخفی‌کردن نیست. ساده بماند.
- اگر کیبورد باز شد (فوکوس روی input)، tab bar مخفی شود.

### ۴.۳ `HeroCarousel` (فقط صفحه‌ی خانه)
- کارت با margin 12px از کنار، ارتفاع **430px** (روی صفحه‌های کوتاه `min(430px, 56svh)`)، شعاع 30px، `overflow: hidden`, `isolation: isolate`، سایه‌ی `0 22px 44px -20px #6732574d`.
- لایه‌ها: تصویر پوستر (`object-fit: cover`) ← گرادیان تیره از `transparent` در ۲۰٪ بالا تا `color-mix(plum-3 96%)` در پایین ← محتوا پایین‌چسب.
- محتوا (padding 20/18): ردیف چیپ‌ها (امتیاز با ستاره روی `--primary`، فصل، تعداد قسمت؛ چیپ‌های دیگر سفید ۱۵٪ با blur) ← عنوان 27px سفید ← خلاصه‌ی ۲ خطی با 82٪ شفافیت ← نقطه‌های pagination (فعال: 20×6px سفید، بقیه 6px با ۳۳٪).
- **رفتار:** `scroll-snap-type: x mandatory` افقی، ۴ تا ۵ آیتم، swipe کاربر کنترل می‌کند. autoplay نگذار. **هیچ دکمه‌ای روی hero وجود ندارد.** کل کارت لینک به صفحه‌ی جزئیات آن عنوان است. ضربه روی کارت به صفحه‌ی جزئیات می‌رود.
- اگر تصویر لود نشد، همان گرادیان آلویی دسکتاپ پس‌زمینه شود.
- حالت loading: skeleton هم‌اندازه با shimmer ملایم (`--shimmer-angle` موجود).


### ۴.۴ `QuickChips`
- ردیف افقی scrollable زیر hero، padding افقی 16px، بدون scrollbar.
- چیپ‌ها: ارتفاع 38px، pill، متن 13px/700، پس‌زمینه‌ی `--card` + حاشیه‌ی `--border`، رنگ `--secondary-foreground`.
- محتوا: امروز پخش می‌شود · فصل جاری · برترین‌ها · تازه‌ها · اخبار (هرکدام لینک به صفحه‌ی مربوط). چیپی که صفحه‌ی فعلی است `--secondary` پر می‌شود.

### ۴.۵ `SectionHeader`
- عنوان 17px/800 سمت شروع، لینک «همه» با فلش کوچک سمت پایان (`--primary`, 12.5px/700). فلش در RTL به **چپ** اشاره می‌کند.

### ۴.۶ `Rail` و `PosterCard`
- `Rail`: `display: flex; gap: 12px; overflow-x: auto; scroll-snap-type: x proximity; padding-inline: 16px; scrollbar-width: none`. (padding انتهایی هم 16px؛ `scroll-padding-inline: 16px`)
- `PosterCard` (در ریل): عرض **124px**، کاور نسبت ۲:۳ (ارتفاع ~178px)، شعاع 14px، سایه‌ی آلویی.
  - روی کاور بالا-ابتدا: بج امتیاز (پس‌زمینه‌ی `plum-3` با ۷۰٪ + blur، سفید، 11px/700، شعاع 9px، با ستاره).
  - زیر کاور: عنوان 12.5px/700 در **حداکثر ۲ خط** (`line-clamp: 2`)، متا 11px با `--muted-foreground` («سریال · ۱۲ قسمت»).
- `PosterCard` در گرید دو‌ستونه (کاتالوگ): عرض `auto`، ارتفاع کاور ~206px، gap `16px 12px`.
- برای تصاویر: `loading="lazy"`, `decoding="async"`, و ابعاد ثابت (`aspect-ratio: 2/3`) تا layout shift نداشته باشیم.

### ۴.۷ `RankRow` (برترین‌ها)
- گرید چهارستونه: `30px | 48px | 1fr | auto`، gap 12px، padding `10px 12px 10px 14px`، شعاع 18px، پس‌زمینه‌ی `--card`، حاشیه‌ی ظریف `inset 0 0 0 1px` از `--border` با ۶۰٪ و سایه‌ی `0 1px 2px #2f1d2b0d`.
- ستون ۱: شماره‌ی رتبه 18px/800 (رتبه‌های ۱ تا ۳ `--primary`، بقیه `--muted-foreground`).
- ستون ۲: کاور 48×66، شعاع 10px.
- ستون ۳: عنوان 14px/700 (یک خط با ellipsis) + متا 11.5px.
- ستون ۴: pill امتیاز (پس‌زمینه‌ی `--secondary`، متن `--secondary-foreground`، 12.5px/800، ستاره‌ی توپر).
- فاصله‌ی بین ردیف‌ها 8px. حالت `:active` → `transform: scale(.985)`.

### ۴.۸ `FilterSheet` (bottom sheet)
- با دکمه‌ی «فیلتر» باز می‌شود. روی صفحه یک scrim (`plum-3` با ۵۵٪) و sheet از پایین با شعاع بالای 30px، `max-height: 85svh`، محتوا داخلش scroll می‌شود.
- بالای sheet: دستگیره‌ی 40×5px، عنوان «فیلتر» 18px/800 و لینک «پاک‌کردن همه» (`--primary`).
- گروه‌ها: ژانر، وضعیت، ترتیب. هر گروه عنوان 13px/700 `--muted-foreground` و چیپ‌های wrap‌شونده (ارتفاع 36px). انتخاب‌شده: `--secondary` + رنگ `--secondary-foreground`.
- پایین: دکمه‌ی تمام‌عرض `--primary` با ارتفاع 52px: **«نمایش ۱۲۴ نتیجه»** (عدد زنده بر اساس فیلتر).
- بستن: ضربه روی scrim، swipe-down روی دستگیره، کلید Escape. فوکوس داخل sheet محبوس شود (`role="dialog"`, `aria-modal="true"`) و بعد از بستن به دکمه‌ی فیلتر برگردد.
- ورودی/خروجی: `transform: translateY(100%)` ← `0` در 280ms با `cubic-bezier(.2,.8,.3,1)`.

### ۴.۹ `DetailHeader` (صفحه‌ی جزئیات)
- پس‌زمینه‌ی بالا (ارتفاع ~300px): همان کاور بلور‌شده (`filter: blur(26px) saturate(1.2)`، `scale(1.15)`) با گرادیان از `plum-3` ۵۵٪ تا `--background` در پایین.
- دکمه‌ی بازگشت و اشتراک‌گذاری شیشه‌ای در TopBar شفاف.
- کاور **118×170** با شعاع 18px و سایه‌ی عمیق، سمت شروع؛ کنارش عنوان فارسی 23px/800 سفید و عنوان انگلیسی/اصلی 12.5px (`direction: ltr; text-align: end`).
- `StatsStrip` زیر آن: کارت سفید با سه سلول مساوی و جداکننده‌ی عمودی: **امتیاز** (عدد رز 19px/800) · **رتبه** · **محبوبیت**.

### ۴.۱۰ `SegmentedTabs`
- محفظه‌ی `--muted` با padding 4px و شعاع 15px؛ تب‌ها `flex: 1`، 13px/700. تب فعال: پس‌زمینه‌ی `--card`، متن `--foreground`، سایه‌ی ریز.
- تب‌ها: **خلاصه · اطلاعات · تیم تولید · مرتبط** (محتوای فعلی صفحه‌ی جزئیات را بین این‌ها تقسیم کن، تمام ستون‌های `detail-sidebar` و `anime-profile` دسکتاپ را در همین تب‌ها بیاور).
- هر تب `role="tab"` با `aria-selected`؛ تعویض محتوا بدون انیمیشن سنگین (فقط crossfade ۱۲۰ms).

### ۴.۱۱ `ActionBar` (جزئیات)
- `position: fixed; inset-inline: 0; bottom: 0; padding: 12px 16px calc(12px + env(safe-area-inset-bottom))`، شیشه‌ای مثل tab bar و خط بالا `--border`.
- راست: دکمه‌ی اصلی **«افزودن به فهرست»** (`--primary`، ارتفاع 52px، شعاع 17px، 15px/700، `flex: 1`). بعد از افزودن، متن «در فهرست شماست» با آیکون تیک و رنگ `--secondary` (و ضربه یعنی تغییر وضعیت/حذف از طریق sheet).
- چپ: دکمه‌ی مربعی 52px برای «امتیاز من» (ستاره) که یک sheet امتیاز ۱ تا ۱۰ باز می‌کند.
- متن دکمه‌ها همان متن‌های فعلی سایت («افزودن به فهرست»، «حذف از فهرست»، «امتیاز من»، «تغییر وضعیت این عنوان»).

### ۴.۱۲ `MoreSheet` («بیشتر»)
- bottom sheet با لیست ۲ ستونه‌ی کاشی‌های ۵۶px (آیکون + برچسب). همه‌ی بخش‌هایی که قبلاً در منو/سایدبار بودند:
  اخبار، نقد و بررسی‌ها، پیشنهادها، فصلی، برترین انیمه، برترین مانگا، شخصیت‌ها، افراد، استودیوها/ناشران، اجتماع، انجمن، باشگاه‌ها، اعضا، ویدیوها، تصاویر، تقویم/جدول پخش، فروشگاه، درباره، تبلیغات، تماس.
- پایین sheet: دکمه‌ی تغییر تم (روشن/تاریک)، تغییر زبان (در صورت وجود)، و ورود/خروج.
- گروه‌بندی با عنوان‌های ساده («کاوش»، «اجتماع»، «درباره»). ترتیب دقیق را از منوی دسکتاپ بگیر.

4. **انیمه‌های فصل**: `Rail` از `PosterCard`
5. **برترین انیمه‌ها**: ۵ `RankRow` + «همه»
6. **تازه‌ترین پیشنهادها**: ریل کارت‌های عریض (۲۳۲px، تصویر ۱۳۰px با شعاع 20px، عنوان ۲ خطی، متای «۶ عنوان · از میز تحریریه»)
7. **تازه‌های مانگا**: `Rail`
8. **اخبار تازه**: ۳ کارت افقی (تصویر مربعی ۷۶px + عنوان ۲ خطی + «۲ ساعت پیش · تحریریه»)
9. **تازه‌ترین نقد و بررسی‌ها**: ریل کارت
10. فوتر فشرده: لینک‌های درباره/تبلیغات/تماس به‌صورت یک ردیف wrap‌شونده با متن 12px و حق نشر.

محتوای `sidebar` و `right-column` دسکتاپ در همین ترتیب جذب می‌شود و ستون جداگانه نمی‌سازد.

### ۵.۲ کاتالوگ (`/anime`, `/manga`)
1. عنوان صفحه («انیمه») 24px/800 + آواتار.
2. فیلد جستجو: pill 48px (`--radius-field: 999px`)، آیکون ذره‌بین، متن «جستجوی عنوان». ثابت (sticky) زیر TopBar نمی‌شود، اما ردیف چیپ‌ها می‌شود (بعد از اسکرول به `top: 52px` می‌چسبد).
3. ردیف چیپ‌ها: دکمه‌ی **«فیلتر · N»** (پر، `--primary`، با آیکون sliders و تعداد فیلتر فعال) + چیپ‌های ژانرهای محبوب/فیلترهای فعال.
4. ردیف شمارنده: «**۳۶۴** عنوان» سمت شروع و «مرتب‌سازی: رتبه» سمت پایان (ضربه روی آن یک sheet ساده‌ی ترتیب باز می‌کند؛ همان گزینه‌های ترتیب `FilterSheet`).
5. گرید ۲ ستونه از `PosterCard`. pagination فعلی را با **infinite scroll** (IntersectionObserver) جایگزین کن؛ اگر API صفحه‌بندی دارد، دکمه‌ی «نمایش بیشتر» هم به‌عنوان fallback داشته باش.
6. حالت خالی: «عنوانی با این فیلترها پیدا نشد.» + دکمه‌ی «پاک‌کردن فیلترها».
7. `catalog-controls` دسکتاپ (چند select و label) در موبایل رندر نمی‌شود و جایش `FilterSheet` است.

### ۵.۳ جزئیات انیمه/مانگا (`/anime/:id`, `/manga/:id`)
ترتیب: `DetailHeader` ← `SegmentedTabs` ← محتوای تب ← `ActionBar` (ثابت).
- **خلاصه:** متن خلاصه‌ی داستان با clamp به ۵ خط و دکمه‌ی «بیشتر» (در همان جا باز می‌شود)، چیپ‌های ژانر (`--secondary`)، تریلر/ویدیوها (ریل افقی با نسبت 16:9).
- **اطلاعات:** گرید ۲ستونه‌ی `facts` (کارت سفید، خانه‌ها با خط ۱px از `--border`؛ برچسب 11.5px muted، مقدار 13.5px/700): نوع، قسمت‌ها، وضعیت، استودیو، فصل، منبع، رده‌ی سنی و … هر مقدار موجود در سایت. مقدار ناموجود: «در داده‌ی محلی ذکر نشده» (همان متن فعلی).
- **تیم تولید:** لیست ردیفی (آواتار گرد 44px + نام + نقش).
- **مرتبط:** ریل «انیمه‌های مرتبط» و «پیشنهادها».

### ۵.۴ صفحه‌های رتبه‌بندی (`/top/anime`, `/top/manga`) و فصلی (`/seasonal`)
- لیست تک‌ستونه‌ی `RankRow` با تعداد زیاد؛ بالا یک `SegmentedTabs` برای دسته‌بندی‌ها (مثلاً «برترین‌ها · در حال پخش · به‌زودی» یا فصل‌ها).
- برای `/seasonal` سگمنت فصل‌ها + گرید ۲ستونه.

### ۵.۵ جستجو (overlay)
- تمام‌صفحه، فیلد جستجوی خودکار فوکوس‌شده بالا + دکمه‌ی «بستن»؛ زیر آن «جستجوهای اخیر» (چیپ) و نتایج زنده به‌صورت `RankRow` فشرده. حالت خالی: «چیزی پیدا نشد. املای عنوان را بررسی کن یا ژانر را امتحان کن.»

### ۵.۶ داشبورد / فهرست من (`/dashboard`)
- بالا: کارت خوش‌آمد با آواتار، نام، و ۳ آمار (در حال تماشا / تمام شده / برای بعد) به‌صورت `StatsStrip`.
- زیر آن `SegmentedTabs` وضعیت فهرست (در حال دیدن · تمام شده · برای بعد · ...) به‌جای `list-tabs` دسکتاپ.
- فهرست: گرید `repeat(auto-fill, minmax(128px, 1fr))` از کارت‌ها یا `RankRow` (کاربر با یک دکمه‌ی کوچک بین دو نمایش جابجا شود).
- تنظیمات حساب و خروج: داخل `MoreSheet` / صفحه‌ی جداگانه، نه وسط داشبورد.

### ۵.۷ پروفایل کاربر (`/user/:username`)
- بنر بالا با گرادیان آلویی و آواتار بزرگ روی آن، نام 1.6rem، دکمه‌ی «دنبال کردن» تمام‌عرض زیر نام. آمار ('stamp') به‌صورت `StatsStrip`. تب‌ها: فهرست · فعالیت · درباره.

### ۵.۸ ورود / ثبت‌نام (`/login`, `/register`)
- بدون TabBar. کارت تک‌ستونه وسط صفحه، فیلدهای pill با ارتفاع 52px، دکمه‌ی اصلی تمام‌عرض 52px، لینک ثانویه («حساب نداری؟») زیر دکمه. کیبورد باز شود، دکمه بالای کیبورد دیده شود (`scroll-padding`).

### ۵.۹ سایر صفحه‌ها (اخبار، نقد، انجمن، باشگاه‌ها، ...)
- همان الگو: TopBar + محتوای تک‌ستونه با کارت‌های ۱۸px + TabBar. لیست‌ها از `RankRow`/کارت افقی استفاده کنند؛ جدول‌ها (در صورت وجود) به لیست کارتی تبدیل شوند، نه اسکرول افقی.

## ۶. تعامل و حرکت (کم و فقط پاسخ به لمس)

- `:active` روی کارت‌ها و دکمه‌ها: `transform: scale(.97–.985)` در 120ms. hover فقط زیر `@media (hover: hover)`.
- sheet: ورود/خروج 280ms. تعویض hero: خود snap اسکرول. تعویض تب جزئیات: crossfade 120ms.
- **هیچ انیمیشن ورود خودکار برای سکشن‌ها نگذار** (fade-up روی همه چیز ممنوع).
- `@media (prefers-reduced-motion: reduce)`: همه‌ی transitionها و shimmer خاموش.
- `-webkit-tap-highlight-color: transparent` و `touch-action: manipulation` روی دکمه‌ها.
- `overscroll-behavior: contain` روی sheetها.

## ۷. دسترس‌پذیری

- فوکوس قابل‌مشاهده روی همه‌ی کنترل‌ها (`outline: 2px solid var(--ring); outline-offset: 2px`).
- tab bar: `<nav aria-label="ناوبری اصلی">` و آیتم فعال `aria-current="page"`.
- همه‌ی دکمه‌های آیکونی `aria-label` فارسی دارند (جستجو، بازگشت، اشتراک‌گذاری، امتیاز).
- تصاویر کاور `alt` = عنوان.
- کنتراست متن روی hero با گرادیان تیره باید ≥ 4.5:1 باشد (گرادیان پایین را کوتاه نکن).
- عددها فارسی همان‌طور که در سایت هستند، بدون تغییر.

## ۸. ترتیب پیشنهادی پیاده‌سازی

1. `useIsMobile` + app shell (`TopBar`, `BottomTabBar`) و مخفی‌کردن layout سه‌ستونه در موبایل.
2. صفحه‌ی خانه: `HeroCarousel`, `QuickChips`, `Rail`, `PosterCard`, `RankRow`, `SectionHeader`.
3. کاتالوگ: جستجو، `FilterSheet`، گرید دوستونه، infinite scroll.
4. جزئیات: `DetailHeader`, `StatsStrip`, `SegmentedTabs`, `ActionBar`.
5. `MoreSheet` و overlay جستجو.
6. داشبورد، پروفایل، ورود/ثبت‌نام و صفحه‌های بقیه.
7. بررسی تم تاریک، reduced-motion، safe-area و صفحه‌های کوچک (۳۶۰px) و بزرگ (۴۳۰px، تبلت ۷۶۸px).

## ۹. چک‌لیست پذیرش

## ۱۰. نکته‌ی مهم درباره‌ی این طراحی

این طرح بر اساس تحلیل کد و CSS منتشرشده‌ی سایت (توکن‌ها، کلاس‌ها، روت‌ها و متن‌ها) ساخته شده، نه اسکرین‌شات زنده. اسم کلاس‌ها و ساختار صفحه‌های داشبورد/پروفایل را از CSS استنباط کرده‌ام. اگر ساختار داده‌ی واقعی (مثلاً فیلدهای یک عنوان) فرق داشت، ساختار بصری همین است و فقط فیلدها را با داده‌ی واقعی تطبیق بده. عنوان‌ها و عددهای تصویر مرجع نمونه‌اند.
